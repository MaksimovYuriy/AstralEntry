# AstralEntry

HTTP-сервис для хранения документов, реализованный на Go в рамках тестового задания уровня Middle. Пользователь может загружать JSON и файлы, управлять своей коллекцией и предоставлять другим пользователям доступ к отдельным документам.

## Возможности

- регистрация пользователей по токену администратора;
- аутентификация и серверные сессии с ограниченным сроком действия;
- загрузка JSON и файлов через `multipart/form-data`;
- публичные и приватные документы;
- выдача доступа пользователям через `grant`;
- фильтрация, сортировка и пагинация списка документов;
- получение JSON или скачивание файла;
- поддержка `HEAD` и range-запросов для файлов;
- удаление документов владельцем;
- Redis cache-aside для списков, JSON и небольших файлов;
- PostgreSQL-миграции через Goose;
- graceful shutdown HTTP-сервера;
- запуск приложения, PostgreSQL и Redis через Docker Compose.

## Стек

- Go 1.26 и `net/http`;
- PostgreSQL 18, `database/sql` и pgx;
- Redis и `go-redis`;
- Goose;
- bcrypt;
- cleanenv;
- Docker Compose.

## Архитектура

Основной поток обработки запроса:

```text
HTTP Controller
      ↓
Bearer Middleware
      ↓
Cached Document UseCase
      ├── Redis
      └── Document UseCase
              ├── PostgreSQL Repository
              └── Local File Storage
```

## Запуск через Docker Compose

Требуются Docker и Docker Compose.

Создать конфигурацию:

```bash
cp .env.example .env
```

Перед запуском необходимо задать:

```dotenv
DB_PASSWORD=change-me
AUTH_ADMIN_TOKEN=change-me
```

Запустить стек:

```bash
docker compose up --build -d
```

Остановка:

```bash
docker compose down
```

## API

Пользовательский токен передаётся в защищённых запросах через заголовок `Authorization: Bearer <token>`.

| Метод | Endpoint | Авторизация | Назначение |
|---|---|---|---|
| `POST` | `/api/register` | Токен администратора в форме | Регистрация пользователя |
| `POST` | `/api/auth` | Нет | Получение токена сессии |
| `DELETE` | `/api/auth` | Bearer | Завершение текущей сессии |
| `POST` | `/api/docs` | Bearer | Загрузка документа |
| `GET`, `HEAD` | `/api/docs` | Bearer | Получение списка документов |
| `GET`, `HEAD` | `/api/docs/<id>` | Bearer | Получение содержимого документа |
| `DELETE` | `/api/docs/<id>` | Bearer | Удаление документа владельцем |

### `POST /api/register`

Принимает форму `application/x-www-form-urlencoded`:

| Поле | Описание |
|---|---|
| `token` | Фиксированный токен администратора из конфигурации |
| `login` | Минимум 8 латинских букв или цифр |
| `pswd` | Минимум 8 символов, разные регистры, цифра и специальный символ |

Возвращает зарегистрированный логин в поле `response`.

### `POST /api/auth`

Принимает форму `application/x-www-form-urlencoded` с полями `login` и `pswd`. Возвращает токен сессии в поле `response`. В PostgreSQL хранится только SHA-256 токена; срок жизни сессии задаётся через `AUTH_TOKEN_TTL`.

### `DELETE /api/auth`

Принимает токен текущей сессии через Bearer-заголовок, завершает сессию и подтверждает операцию в поле `response`.

### `POST /api/docs`

Принимает `multipart/form-data`:

| Поле | Описание |
|---|---|
| `meta` | JSON с метаданными документа |
| `json` | Произвольные JSON-данные; опционально |
| `file` | Файл; опционально |

Модель `meta`:

| Поле | Тип | Описание |
|---|---|---|
| `name` | string | Имя документа или файла |
| `file` | boolean | Признак наличия файла |
| `public` | boolean | Доступность всем авторизованным пользователям |
| `mime` | string | MIME документа |
| `grant` | string[] | Логины пользователей с доступом |

Документ должен содержать JSON, файл либо оба значения. `name` и `mime` должны соответствовать загружаемому файлу. Результат загрузки возвращается в поле `data`.

### `GET`, `HEAD /api/docs`

Принимает необязательные query-параметры:

| Параметр | Описание |
|---|---|
| `login` | Логин владельца; без него возвращаются собственные документы |
| `key` | Колонка для фильтрации |
| `value` | Значение фильтра; передаётся вместе с `key` |
| `limit` | Количество документов от 1 до 100; по умолчанию 20 |
| `offset` | Количество пропускаемых документов; по умолчанию 0 |

Для `key` разрешены `id`, `name`, `mime`, `file`, `public` и `created`. Документы сортируются по имени по возрастанию, затем по дате создания по убыванию. `HEAD` возвращает те же заголовки без тела.

### `GET`, `HEAD /api/docs/<id>`

Принимает UUID документа в path. JSON возвращается в поле `data`; файл отдаётся напрямую с сохранённым MIME и исходным именем. `HEAD` возвращает заголовки без содержимого.

### `DELETE /api/docs/<id>`

Принимает UUID документа в path. Удаление разрешено только владельцу. Поле `response` содержит UUID удалённого документа и результат операции.

## Права доступа

- владелец видит и удаляет свои документы;
- пользователь из `grant` может читать приватный документ;
- любой авторизованный пользователь может читать публичный документ;
- `grant` и `public` не дают права удаления;
- ответы с ошибками не кэшируются.

## Формат ответа и статусы

Общая модель:

```json
{
  "error": {
    "code": 400,
    "text": "invalid request"
  },
  "response": {},
  "data": {}
}
```

Поля `error`, `response` и `data` присутствуют только при наличии соответствующего значения.

| Статус | Значение |
|---:|---|
| 200 | Запрос выполнен |
| 400 | Некорректные параметры или документ не найден |
| 401 | Пользователь не авторизован |
| 403 | Нет прав доступа |
| 405 | Метод не поддерживается для маршрута |
| 500 | Внутренняя ошибка |
| 501 | Метод ещё не реализован |

Файлы выдаются непосредственно, без JSON-оболочки.

## Кэш

Redis используется по стратегии cache-aside:

1. `GET/HEAD` проверяет Redis;
2. при cache miss данные читаются из PostgreSQL или файлового хранилища;
3. результат сохраняется в Redis с TTL;
4. при недоступности Redis запрос продолжает работать через основные хранилища.

Кэшируются:

- списки документов;
- JSON-документы;
- файлы размером не больше `REDIS_MAX_FILE_SIZE`.

## Тестирование

Unit-тесты и статическая проверка:

```bash
go test ./...
go vet ./...
```

Интеграционный тест для проверки кэша:

```bash
go test ./internal/controller/restapi
```

Тест проверяет cache miss, cache hit, инвалидацию после удаления и JSON-ответ `405`. Если локальный Redis недоступен, тест пропускается. Другой адрес можно указать через необязательную переменную `REDIS_TEST_ADDRESS`.

## Отличия от исходного API

В задании способ передачи пользовательского токена для большинства методов не зафиксирован, а logout помещает токен в URL. В проекте используется `Authorization: Bearer`, чтобы токены не попадали в URL и логи.

Поэтому logout реализован как:

```http
DELETE /api/auth
Authorization: Bearer <token>
```

Также используются UUID документов и добавлен параметр `offset` для доступа к следующим страницам списка.
